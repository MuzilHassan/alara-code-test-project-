# QW-015 — Edit and Delete actions with confirmation

Renders Edit button (navigates to S-02) and Delete button (shows confirmation, on confirm calls repository deleteTask and navigates to S-01).

**Contract:** Props: { task, onEdit, onDelete }; onDelete shows confirm dialog, calls deleteTask, navigates to S-01

## Why

Users need to be able to edit an existing task by navigating to a pre-populated Add/Edit screen, and to permanently delete a task and its associated note after confirming, returning to the day view afterward.

## What

An action bar component with Edit and Delete buttons that accepts props { task, onEdit, onDelete }, shows a confirmation dialog on delete, calls deleteTask, and navigates to S-01 on confirm.

## Scope

**In:** Rendering Edit and Delete buttons with 44x44px minimum tappable areas; showing a confirmation dialog on delete; calling the DC-002-01 deleteTask contract; navigating to S-02 on edit and S-01 on delete-confirm via the DC-003-02 navigation contract.

**Out:** Does not render the task title, date, status, or note content (that is DC-006-01); does not implement the S-02 Add/Edit form fields or save logic; does not implement the S-01 day view itself.

## Tasks

- [ ] **T1** — Scaffold the action component accepting props { task, onEdit, onDelete } and render Edit and Delete buttons with tappable areas of at least 44x44 pixels each. _(verify: Measuring the Edit and Delete buttons on S-03 shows each has a rendered area of at least 44 pixels high and 44 pixels wide per TC-054)_
- [ ] **T2** — Wire the onEdit handler to call the DC-003-02 navigateTo('S-02', { taskId: task.id, mode: 'edit' }) interface so the Add/Edit screen opens pre-populated with the task's data. _(verify: Clicking the Edit action on S-03 navigates to S-02 with the title input and date picker pre-populated with the task's existing values per TC-041)_
- [ ] **T3** — Implement the Delete confirmation dialog that appears when the Delete button is activated, with Confirm and Cancel options. _(verify: Clicking the Delete action on S-03 displays a confirmation dialog before any deletion occurs per TC-025)_
- [ ] **T4** — Wire the Cancel action on the confirmation dialog so it dismisses the dialog and leaves the task and its note unchanged. _(verify: Clicking Cancel on the confirmation dialog returns to S-03 without modifying the task or its associated note per TC-025)_
- [ ] **T5** — Wire the Confirm action to call the DC-002-01 deleteTask(task.id) contract and then the DC-003-02 navigateTo('S-01') interface, ensuring both the task and its note are permanently deleted. _(verify: Clicking Delete then Confirm deletes the task and its note from the repository and navigates to the Day View (S-01) per TC-026 and TC-024)_

## Acceptance

- Given the user initiates deletion of a task, when the system prompts for confirmation, then the user must confirm before the task is deleted.
- Given the user initiates deletion of a task that has an associated note, when the user confirms the deletion, then the system permanently deletes both the task and its associated note.
- Given the user initiates deletion of a task, when the user cancels the confirmation, then the task and its note remain unchanged.
- Given the user is on the day view screen S-01, when the user activates the add button, then the system navigates to the Add/edit task screen S-02.
- Given the user is on the day view screen S-01, when the user selects a task in the list, then the system navigates to the Task detail screen S-03 for that task.
- Given the user is on the Task detail screen S-03, when the user activates the Edit action, then the system navigates to the Add/edit task screen S-02 pre-populated with that task's data.
- Given the user is on the Add/edit task screen S-02, when the user activates Save or Cancel, then the system navigates back to the appropriate prior screen.
- Given the user is on the Task detail screen S-03, when the user activates the Delete action, then the system prompts for confirmation and upon confirmation navigates back to the day view screen S-01.
