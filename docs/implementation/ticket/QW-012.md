# QW-012 — Note textarea with character counter

Renders a textarea for free-text notes with maxlength=2000, live counter, support for line breaks, and validation.

**Contract:** Props: { initialNote?, onNoteChange }; State: note string; Renders textarea + counter

## Why

Allows users to enter free-text notes up to 2000 characters with line breaks while enforcing the character limit and providing live feedback.

## What

A textarea component for notes with maxlength=2000, a live character counter, support for line breaks, and validation handling.

## Scope

**In:** Note textarea rendering, state management for note string, live character counter, and onNoteChange callback.

**Out:** Title input, date picker, save/cancel wiring, and note persistence logic.

## Tasks

- [ ] **T1** — Scaffold the note textarea component accepting props { initialNote?, onNoteChange } and initialize state with initialNote or empty string _(verify: Component renders a textarea pre-populated with initialNote when provided, and empty when not)_
- [ ] **T2** — Implement the live character counter displaying current length relative to the 2000-character maximum _(verify: Typing 100 characters into the note textarea displays a counter in '100/2000' format)_
- [ ] **T3** — Enforce maxlength=2000 on the textarea to block or truncate typing and pasting beyond 2000 characters, while supporting line breaks _(verify: Pasting a 2500-character string into the note textarea results in the value being truncated to 2000 characters; line breaks are preserved)_
- [ ] **T4** — Wire onNoteChange callback to propagate note state changes to the parent component _(verify: Parent component receives the updated note string via onNoteChange whenever the user types, pastes, or clears text)_

## Acceptance

- Given the user is on the task detail view of a task, when the user adds a free-text note of up to 2000 characters with line breaks and saves, then the system stores the note content and a last-updated timestamp and displays the note on the task detail view.
- Given the user is on the task detail view of a task that has an existing note, when the user edits the note content and saves, then the system updates the note and its last-updated timestamp.
- Given the user is on the task detail view of a task that has an existing note, when the user clears all text from the note field and saves, then the system treats the note as deleted and no note is associated with the task.
- Given the day view is displaying a task list, when a task has a non-empty note, then the system displays a note indicator icon next to that task in the day view.
- Given the user is editing a note, when the entered text exceeds 2000 characters, then the system prevents entry beyond the limit or displays a validation error.
- Given the user is entering a task title on the Add/edit task screen S-02, when the user types or pastes text, then the system enforces a maximum of 200 characters and displays a character counter showing the current count relative to the maximum.
- Given the user is entering a note on the Add/edit task screen S-02, when the user types or pastes text, then the system enforces a maximum of 2000 characters and displays a character counter showing the current count relative to the maximum.
- Given the application is displayed on a screen 320 pixels wide, when the user interacts with any screen, then all content and controls are visible and usable without horizontal scrolling that obscures functionality.
- Given the user is interacting with any tappable control in the application, when the control is rendered, then its tappable area is at least 44 pixels high and 44 pixels wide.
