# QW-002 — Task CRUD operations with validation

Implements createTask, updateTask, getTasksForDate, and deleteTask with title length validation, date defaulting, status management, and sorting logic.

**Contract:** createTask({title, date?}): Result<Task>; updateTask(id, {title?, date?}): Result<Task>; getTasksForDate(date): Task[]; deleteTask(id): Result<void>

## Why

Users need to create, edit, view, and delete tasks for any given date with title validation and date assignment, satisfying core task management requirements.

## What

A repository module exposing createTask, updateTask, getTasksForDate, and deleteTask, with title length validation (1–200 chars), date defaulting to the selected date, Open status on creation, date-based retrieval, and cascade deletion of associated notes via the storage layer.

## Scope

**In:** Task CRUD operations, title validation (1–200 chars), date defaulting, status set to Open on creation, retrieval by date, and cascade deletion delegating to the storage layer.

**Out:** Completion toggling logic (handled in DC-002-02), note content CRUD and 2000-char validation (handled in DC-002-03), UI rendering and confirmation dialogs, and the underlying storage persistence implementation (DC-001-01).

## Tasks

- [ ] **T1** — Scaffold the Task repository module and wire it to the DC-001-01 storage contract (saveTask, saveNote, deleteTask, loadAllData) for persistence delegation. _(verify: Repository module instantiates with access to saveTask, saveNote, deleteTask, and loadAllData from the storage layer without runtime errors.)_
- [ ] **T2** — Implement createTask({title, date?}) with title validation (reject empty string and titles exceeding 200 characters), date defaulting to the currently selected date when omitted, and status set to Open. _(verify: createTask with title 'Buy groceries' and no date returns a Task with the default date and status 'Open'; createTask with '' returns a validation error; createTask with a 201-character title returns a validation error.)_
- [ ] **T3** — Implement updateTask(id, {title?, date?}) with the same title validation rules, persisting updated title and/or date values through the storage layer. _(verify: updateTask('t1', {title: 'New title', date: '2024-02-01'}) returns a Task with updated values; updateTask('t1', {title: ''}) and updateTask('t1', {title: 201-char string}) both return validation errors.)_
- [ ] **T4** — Implement getTasksForDate(date) that retrieves all tasks for the given date and sorts them with Open tasks first followed by Completed tasks. _(verify: getTasksForDate returns only tasks whose date matches the argument, ordered with Open tasks before Completed tasks.)_
- [ ] **T5** — Implement deleteTask(id) that deletes the task and cascades deletion of its associated note by delegating both removals to the storage layer. _(verify: After deleteTask('t1'), neither task 't1' nor its associated note 'n1' can be retrieved from the repository.)_

## Acceptance

- Given the user is on the day view viewing a selected date, when the user creates a new task by entering a title between 1 and 200 characters and saving without explicitly choosing a date, then the system creates the task assigned to the currently selected date with a status of Open.
- Given the user is creating a task, when the user enters a title and selects a past or future date via the date picker, then the system creates the task on that selected date with a status of Open.
- Given the user is creating a task, when the user attempts to save without entering a title or enters a title exceeding 200 characters, then the system prevents creation and displays a validation error.
- Given the user is editing an existing task, when the user modifies the title and or date and saves, then the system updates the task with the new title and date values.
- Given the user is editing a task whose original date matched the currently viewed day, when the user changes the task's date to a different date and saves, then the task is removed from the current day view and appears on the newly assigned date's day view.
- Given the user is editing a task, when the user enters a title that is empty or exceeds 200 characters, then the system prevents saving and displays a validation error.
- Given the user initiates deletion of a task, when the system prompts for confirmation, then the user must confirm before the task is deleted.
- Given the user initiates deletion of a task that has an associated note, when the user confirms the deletion, then the system permanently deletes both the task and its associated note.
- Given the user initiates deletion of a task, when the user cancels the confirmation, then the task and its note remain unchanged.
- Given the user is entering a task title on the Add/edit task screen S-02, when the user types or pastes text, then the system enforces a maximum of 200 characters and displays a character counter showing the current count relative to the maximum.
- Given the user is entering a note on the Add/edit task screen S-02, when the user types or pastes text, then the system enforces a maximum of 2000 characters and displays a character counter showing the current count relative to the maximum.
- _(unit)_ createTask returns a Result<Task> that is an error for titles outside the 1–200 character range without mutating storage.
- _(unit)_ deleteTask returns Result<void> and ensures the associated note is also removed from storage.
