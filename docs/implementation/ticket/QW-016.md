# QW-016 — Design tokens and accessibility utilities

CSS file with AA-compliant color palette, spacing tokens, tap-target utility (min 44x44px), focus-visible styles, and screen-reader-only text class.

**Contract:** CSS file exporting: --color-bg, --color-text, --color-primary, --tap-target-min, .tap-target, .sr-only, focus-visible styles

## Why

REQ-NFUNC-002 and REQ-NFUNC-003 require the application to be fully usable at 320px width with WCAG 2.1 AA-compliant contrast, accessible tap targets, and non-color-only status indication. This unit provides the foundational design tokens and utility CSS classes that all screens consume to meet those requirements.

## What

A single CSS file exporting color tokens with AA-compliant contrast ratios, spacing tokens, a --tap-target-min variable, a .tap-target utility enforcing 44x44px minimums, .sr-only for screen-reader-only text, and focus-visible styles for keyboard accessibility.

## Scope

**In:** CSS custom properties for background, text, and primary colors verified against WCAG 2.1 AA ratios; --tap-target-min token; .tap-target utility class enforcing min 44x44px; .sr-only class for visually hidden but screen-reader accessible text; :focus-visible styles providing a visible keyboard focus indicator.

**Out:** Does not build any application screens (Day View, Add/Edit Task, Task Detail), JavaScript logic, or component-level styling — only the shared token and utility foundation those screens consume.

## Tasks

- [ ] **T1** — Define CSS custom properties --color-bg, --color-text, and --color-primary with hex values selected so that text-to-background and primary-to-background combinations achieve at least 4.5:1 contrast for normal text and 3:1 for large text per WCAG 2.1 AA. _(verify: Running a contrast analysis tool against --color-text on --color-bg and --color-primary on --color-bg yields ratios of at least 4.5:1 (normal text) and 3:1 (large text).)_
- [ ] **T2** — Define the --tap-target-min custom property set to 44px and create the .tap-target utility class that applies min-width and min-height of var(--tap-target-min) with box-sizing: border-box and inline-flex centering so child controls fill the tappable area. _(verify: An element with class .tap-target has a computed minimum width and height of 44px, matching the --tap-target-min value.)_
- [ ] **T3** — Create the .sr-only utility class using the standard clip/position/overflow/whitespace technique so text is removed from the visual layout but remains available to assistive technology. _(verify: An element with class .sr-only is not visually rendered but its text content is present in the DOM and accessible to screen readers.)_
- [ ] **T4** — Implement :focus-visible styles that apply a high-contrast outline (at least 2px, using --color-primary or equivalent) to any element receiving keyboard focus, while not triggering on mouse clicks via :focus:not(:focus-visible) suppression. _(verify: Tabbing to an element shows a visible high-contrast outline; clicking the same element with a mouse does not show the outline.)_
- [ ] **T5** — Add responsive base styles on a root container or body ensuring content adapts to 320px width without horizontal overflow, using width: 100%, max-width: 100vw, overflow-x: hidden, and box-sizing: border-box as a foundation. _(verify: Rendering a page consuming this CSS at 320px viewport width produces no horizontal scrollbar and no content is clipped or obscured.)_
- [ ] **T6** — Provide a companion .status-label utility class and document that task status must be conveyed via checkbox state and/or text label (e.g., 'Open'/'Completed') in addition to color, so consuming screens can satisfy the non-color-only status requirement. _(verify: A task row using .status-label alongside a checkbox displays both a checkbox state and a text label, conveying status without relying on color alone.)_

## Acceptance

- Given the application is displayed on a screen 320 pixels wide, when the user interacts with any screen, then all content and controls are visible and usable without horizontal scrolling that obscures functionality.
- Given the user is interacting with any tappable control in the application, when the control is rendered, then its tappable area is at least 44 pixels high and 44 pixels wide.
- Given the application is rendered on any screen, when text is displayed, then all text meets WCAG 2.1 AA contrast ratios against its background.
- Given the day view is displaying tasks with mixed Open and Completed statuses, when the system conveys a task's completion status, then the status is indicated by means other than colour alone, such as a checkbox state and or text label.
- _(unit)_ All color token pairs (text-on-bg, primary-on-bg) achieve WCAG 2.1 AA contrast ratios of at least 4.5:1 for normal text and 3:1 for large text when measured programmatically.
- _(unit)_ The --tap-target-min token is set to 44px and .tap-target elements have a rendered minimum area of 44px by 44px.
- _(unit)_ The .sr-only class hides text visually while keeping it in the accessibility tree.
- _(unit)_ The :focus-visible style produces a visible, high-contrast focus indicator for keyboard navigation only.
