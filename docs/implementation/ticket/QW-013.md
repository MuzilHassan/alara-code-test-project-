# QW-013 — Save/Cancel actions with error handling and navigation

Wires Save to call repository create/update, handles validation and storage errors by preserving input and showing messages, and navigates back on success or Cancel.

**Contract:** onSave(): validates, calls repository, shows error or navigates back; onCancel(): navigates back without saving

## Why

Wires the Add/Edit Task screen's Save and Cancel actions to create or update tasks, persist notes, handle storage errors gracefully, and navigate between screens.

## What

Save/Cancel action handlers that validate input, call repository create/update/saveNote, display errors on failure while preserving input, and navigate back on success or cancel.

## Scope

**In:** onSave handler wiring to createTask/updateTask/saveNote, onCancel handler, storage error handling with input preservation, validation gate before repository calls, and navigation via goBack.

**Out:** Rendering of the title input, date picker, and note textarea internals.

## Tasks

- [ ] **T1** — Wire DC-005-01, DC-005-02, and DC-005-03 components into the Add/Edit Task screen, passing props and collecting state via their onTitleChange, onDateChange, and onNoteChange callbacks _(verify: All three sub-components render together on S-02 and report their state changes to the screen container)_
- [ ] **T2** — Determine add vs edit mode from the navigation contract (DC-003-02 currentScreen params) and pre-populate fields in edit mode by loading the existing task _(verify: In edit mode, title input shows the task's title and date picker shows the task's date; in add mode, fields are empty and date defaults to selected date)_
- [ ] **T3** — Implement onSave to first validate the title (non-empty, ≤200 chars); if invalid, trigger the title component's error display and abort _(verify: Clicking Save with an empty title or a title exceeding 200 characters prevents creation and displays a validation error)_
- [ ] **T4** — Wire onSave in add mode to call createTask({ title, date }) from DC-002-01 and saveNote from DC-002-03 if note is non-empty _(verify: Clicking Save with valid title 'Meeting prep' and default date creates the task on the selected date with Open status and persists any entered note)_
- [ ] **T5** — Wire onSave in edit mode to call updateTask(id, { title, date }) from DC-002-01 and saveNote from DC-002-03 _(verify: Clicking Save after modifying title and date updates the task with new values; changing date moves the task to the new date's day view)_
- [ ] **T6** — Handle storage errors from createTask/updateTask/saveNote by displaying a clear error message and preserving all user input on screen without navigating away _(verify: When a save operation fails due to storage error, an error message is displayed and the title and note inputs retain their entered values)_
- [ ] **T7** — Implement error message dismissal that keeps user input intact so the user can retry or copy data _(verify: After dismissing the storage error message, the title and note input fields still contain their previously entered data)_
- [ ] **T8** — Implement onCancel to call goBack() from DC-003-02 without performing any save operations _(verify: Clicking Cancel navigates back to S-01 without creating or updating any task)_
- [ ] **T9** — Wire successful onSave to call goBack() to return to the prior screen after persistence succeeds _(verify: Clicking Save with valid input navigates back to S-01 showing the new or updated task in the day view)_

## Acceptance

- Given the user is on the day view viewing a selected date, when the user creates a new task by entering a title between 1 and 200 characters and saving without explicitly choosing a date, then the system creates the task assigned to the currently selected date with a status of Open.
- Given the user is creating a task, when the user enters a title and selects a past or future date via the date picker, then the system creates the task on that selected date with a status of Open.
- Given the user is creating a task, when the user attempts to save without entering a title or enters a title exceeding 200 characters, then the system prevents creation and displays a validation error.
- Given the user is editing an existing task, when the user modifies the title and or date and saves, then the system updates the task with the new title and date values.
- Given the user is editing a task whose original date matched the currently viewed day, when the user changes the task's date to a different date and saves, then the task is removed from the current day view and appears on the newly assigned date's day view.
- Given the user is editing a task, when the user enters a title that is empty or exceeds 200 characters, then the system prevents saving and displays a validation error.
- Given the user is on the task detail view of a task, when the user adds a free-text note of up to 2000 characters with line breaks and saves, then the system stores the note content and a last-updated timestamp and displays the note on the task detail view.
- Given the user is on the task detail view of a task that has an existing note, when the user edits the note content and saves, then the system updates the note and its last-updated timestamp.
- Given the user is on the task detail view of a task that has an existing note, when the user clears all text from the note field and saves, then the system treats the note as deleted and no note is associated with the task.
- Given the day view is displaying a task list, when a task has a non-empty note, then the system displays a note indicator icon next to that task in the day view.
- Given the user is editing a note, when the entered text exceeds 2000 characters, then the system prevents entry beyond the limit or displays a validation error.
- Given the user is on the day view screen S-01, when the user activates the add button, then the system navigates to the Add/edit task screen S-02.
- Given the user is on the day view screen S-01, when the user selects a task in the list, then the system navigates to the Task detail screen S-03 for that task.
- Given the user is on the Task detail screen S-03, when the user activates the Edit action, then the system navigates to the Add/edit task screen S-02 pre-populated with that task's data.
- Given the user is on the Add/edit task screen S-02, when the user activates Save or Cancel, then the system navigates back to the appropriate prior screen.
- Given the user is on the Task detail screen S-03, when the user activates the Delete action, then the system prompts for confirmation and upon confirmation navigates back to the day view screen S-01.
- Given the user performs a create, update, or delete action, when the local storage save fails due to insufficient space or storage unavailability, then the system displays a clear error message explaining the failure and preserves the user's entered input on the current screen.
- Given a storage error has occurred, when the user dismisses the error message, then the user's input remains on screen so the user can retry or copy the data.
