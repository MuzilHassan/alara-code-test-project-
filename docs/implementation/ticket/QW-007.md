# QW-007 — Date header with navigation controls

Renders selected date in header, prev/next day buttons, jump-to-today button, and date picker. All controls are 44x44px minimum.

**Contract:** Props: { selectedDate, onPrev, onNext, onToday, onPickDate }; Renders date header with controls

## Why

Users need to view and navigate between dates to see tasks assigned to specific days, satisfying the requirement to display today's date on launch and allow changing the selected date.

## What

A date header UI component that renders the currently selected date alongside prev/next day buttons, a jump-to-today button, and a date picker, all meeting 44x44px minimum tap target and 320px width constraints.

## Scope

**In:** Rendering the selected date display, prev/next/today navigation buttons, date picker integration, and enforcing 44x44px minimum tap targets on all controls.

**Out:** Rendering the task list, open count, empty state, task sorting logic, and add button — those are handled by DC-004-02 and DC-004-03.

## Tasks

- [ ] **T1** — Scaffold the date header component accepting props { selectedDate, onPrev, onNext, onToday, onPickDate } and render the selectedDate in a formatted header string _(verify: Header renders with selectedDate visible at all times, per TC-012)_
- [ ] **T2** — Implement prev and next day buttons wired to onPrev and onNext callbacks, each with a minimum 44x44px tappable area _(verify: Forward button click advances selectedDate by one day and subscriber is notified; back button moves selectedDate back one day and subscriber is notified; both controls measure at least 44x44px)_
- [ ] **T3** — Implement the jump-to-today button wired to onToday callback with a minimum 44x44px tappable area _(verify: Activating today button sets selectedDate to today's date and subscriber is notified, per TC-015)_
- [ ] **T4** — Implement the date picker control wired to onPickDate callback, opening a picker and emitting the selected date, with a minimum 44x44px tappable area _(verify: Opening the date picker and selecting a date calls onPickDate, header updates to the new date, per TC-017)_
- [ ] **T5** — Verify the header layout fits within a 320px wide screen without horizontal scrolling, ensuring all controls remain visible and usable _(verify: All header content and controls are visible and usable on a 320px wide screen with no horizontal scrolling, per TC-053)_

## Acceptance

- Given the user launches the application, when the day view loads, then the system displays today's date in the header and lists all tasks assigned to today's date.
- Given the day view is displaying tasks for a selected date, when multiple tasks exist with mixed Open and Completed statuses, then the system displays all Open tasks first ordered by creation time oldest first, followed by all Completed tasks ordered by creation time oldest first.
- Given the day view is displaying tasks for a selected date, when there is at least one Open task, then the system displays the count of Open tasks.
- Given the day view is displaying a selected date, when no tasks exist for that date, then the system displays an empty state message indicating no tasks.
- Given the user is on the day view, when the user clicks the back or forward control, then the selected date changes to the previous or next day respectively, the header updates to show the new date, and the task list refreshes immediately to show tasks for that date without a full page reload.
- Given the user is on the day view, when the user activates the jump-to-today action, then the selected date changes to today's date, the header updates, and the task list refreshes immediately.
- Given the user is on the day view, when the user opens the date picker and selects a different date, then the header updates to show the newly selected date and the task list refreshes immediately to show tasks for that date.
- Given the user is navigating dates on the day view, when any date change occurs, then the selected date remains visible in the header at all times.
- Given the application is displayed on a screen 320 pixels wide, when the user interacts with any screen, then all content and controls are visible and usable without horizontal scrolling that obscures functionality.
- Given the user is interacting with any tappable control in the application, when the control is rendered, then its tappable area is at least 44 pixels high and 44 pixels wide.
