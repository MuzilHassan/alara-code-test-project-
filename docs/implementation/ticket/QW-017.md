# QW-017 — Render batching and performance utilities

Provides requestAnimationFrame-based batching for DOM updates and a debounce utility for date picker input. Includes performance guard that logs warnings if any action exceeds 800ms.

**Contract:** batchUpdate(fn): void; debounce(fn, ms): Function; perfGuard(actionName, fn): Result

## Why

User-initiated actions — create, update, delete, and date navigation — must complete and render within 1000ms so the application feels responsive and reliable under REQ-NFUNC-001.

## What

A performance utilities module exposing batchUpdate, debounce, and perfGuard, usable by any UI component that performs DOM updates or handles rapid input.

## Scope

**In:** requestAnimationFrame-based batchUpdate(fn), debounce(fn, ms), and perfGuard(actionName, fn) with warning logging above 800ms.

**Out:** This unit provides the utilities only; it does not wire them into specific components like the day view, task editor, or date picker. Those integrations happen in their respective components.

## Tasks

- [ ] **T1** — Implement batchUpdate(fn) that queues a callback and flushes it inside a requestAnimationFrame, coalescing multiple calls in the same frame into a single batch. _(verify: Calling batchUpdate three times synchronously results in the callback executing once during the next animation frame, not three times.)_
- [ ] **T2** — Implement debounce(fn, ms) returning a function that delays invoking fn until ms milliseconds have elapsed since the last call, resetting the timer on each subsequent call. _(verify: Calling the debounced function twice within 50ms with ms=100 invokes fn exactly once, 100ms after the second call.)_
- [ ] **T3** — Implement perfGuard(actionName, fn) that times fn execution and logs a warning containing actionName when elapsed time exceeds 800ms, returning fn's result unchanged. _(verify: perfGuard('create-task', () => 42) returns 42; when fn takes 900ms a warning including 'create-task' is logged; when fn takes 200ms no warning is logged.)_
- [ ] **T4** — Verify the three utilities together against the performance threshold: wrap a simulated create-task DOM update with perfGuard and batchUpdate, and confirm total elapsed time stays well under 1000ms. _(verify: A simulated action that batches a DOM update and is guarded by perfGuard completes in under 1000ms with no 800ms warning emitted.)_

## Acceptance

- Given the user performs any create, update, delete, or date navigation action, when the action is initiated, then the system completes the action and reflects the result in the UI within 1000 milliseconds.
- _(unit)_ batchUpdate coalesces multiple synchronous calls into a single requestAnimationFrame callback.
- _(unit)_ debounce defers execution until the configured quiet period elapses, supporting date picker input throttling.
- _(unit)_ perfGuard logs a warning when any measured action exceeds 800ms, enabling early detection before the 1000ms threshold is breached.
