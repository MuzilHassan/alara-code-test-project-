# QW-010 — Title input with character counter and validation

Renders title text input with maxlength=200, live counter showing current/200, and validation error display for empty or too-long titles.

**Contract:** Props: { initialTitle?, onTitleChange }; State: title string; Renders input + counter + error

## Why

Allows users to enter a task title while enforcing the 1-200 character limit and providing live feedback on character count and validation errors.

## What

A title text input component with maxlength=200, a live character counter showing current/200, and validation error display for empty or too-long titles.

## Scope

**In:** Title text input rendering, state management for title string, live character counter, validation error display, handling of initialTitle prop, and onTitleChange callback.

**Out:** Date picker, note textarea, save/cancel action wiring, and repository calls.

## Tasks

- [ ] **T1** — Scaffold the title input component accepting props { initialTitle?, onTitleChange } and initialize state with initialTitle or empty string _(verify: Component renders an input field pre-populated with initialTitle when provided, and empty when not)_
- [ ] **T2** — Implement the live character counter displaying current length relative to the 200-character maximum _(verify: Typing 10 characters into the title input displays a counter in '10/200' format)_
- [ ] **T3** — Enforce maxlength=200 on the input to block or truncate typing and pasting beyond 200 characters _(verify: Pasting a 250-character string into the title input results in the value being truncated to 200 characters)_
- [ ] **T4** — Implement validation error display for empty title (when triggered by save attempt) or too-long title _(verify: When validation is triggered with an empty title, an error indicating title is required is displayed)_
- [ ] **T5** — Wire onTitleChange callback to propagate title state changes to the parent component _(verify: Parent component receives the updated title string via onTitleChange whenever the user types or pastes)_

## Acceptance

- Given the user is on the day view viewing a selected date, when the user creates a new task by entering a title between 1 and 200 characters and saving without explicitly choosing a date, then the system creates the task assigned to the currently selected date with a status of Open.
- Given the user is creating a task, when the user enters a title and selects a past or future date via the date picker, then the system creates the task on that selected date with a status of Open.
- Given the user is creating a task, when the user attempts to save without entering a title or enters a title exceeding 200 characters, then the system prevents creation and displays a validation error.
- Given the user is editing an existing task, when the user modifies the title and or date and saves, then the system updates the task with the new title and date values.
- Given the user is editing a task whose original date matched the currently viewed day, when the user changes the task's date to a different date and saves, then the task is removed from the current day view and appears on the newly assigned date's day view.
- Given the user is editing a task, when the user enters a title that is empty or exceeds 200 characters, then the system prevents saving and displays a validation error.
- Given the user is entering a task title on the Add/edit task screen S-02, when the user types or pastes text, then the system enforces a maximum of 200 characters and displays a character counter showing the current count relative to the maximum.
- Given the user is entering a note on the Add/edit task screen S-02, when the user types or pastes text, then the system enforces a maximum of 2000 characters and displays a character counter showing the current count relative to the maximum.
- Given the application is displayed on a screen 320 pixels wide, when the user interacts with any screen, then all content and controls are visible and usable without horizontal scrolling that obscures functionality.
- Given the user is interacting with any tappable control in the application, when the control is rendered, then its tappable area is at least 44 pixels high and 44 pixels wide.
